# Per-Battery训练模式使用说明

## 📚 背景

根据论文方法，应该**为每个电池单独训练一个模型**，而不是将多个电池的数据混合训练。

### 论文方法 vs 原实现

| 方面 | 原实现（main.py） | 论文方法（main_per_battery.py） |
|------|------------------|--------------------------------|
| 数据划分 | 混合3个电池的数据 | 每个电池单独划分 |
| 模型数量 | 1个模型 | 3个模型（每个电池一个） |
| 训练集 | B05前60% + B06前60% + B07前60% | B05前75%单独训练 |
| 测试集 | B05后40% + B06后40% + B07后40% | B05后25%单独测试 |
| 图表X轴 | 样本索引（不连续） | 真实循环编号（连续） |
| 符合论文 | ❌ 不完全符合 | ✅ 完全符合 |

## 🚀 快速开始

### 1. 运行Per-Battery训练

```bash
python main_per_battery.py
```

这将：
- ✅ 为B05训练一个BPINN模型
- ✅ 为B06训练另一个BPINN模型
- ✅ 为B07训练第三个BPINN模型
- ✅ 每个电池独立完成Phase 1和Phase 2训练
- ✅ 保存所有结果到`results_per_battery/`

### 2. 可视化结果

```bash
python plot_per_battery_results.py
```

这将生成：
- `results_per_battery/soh_comparison.png` - 每个电池的SOH预测曲线（论文Fig. 4风格）
- `results_per_battery/error_comparison.png` - MAE和RMSE对比条形图

## ⚙️ 参数配置

编辑 `main_per_battery.py` 中的config字典：

```python
config = {
    'hidden_sizes': [10, 10, 10],           # 隐藏层
    'num_epochs': 2000,                     # Phase 1 epochs
    'learning_rate': 0.001,                 # 学习率
    'lambda_physics': 0.01,                 # 物理约束权重
    'batch_size': 32,                       # Batch大小
    'num_secondary_iterations': 400,        # Phase 2迭代次数
    'secondary_learning_rate': 0.001,       # Phase 2学习率
    'lambda_test_physics': 0.01,            # 测试物理约束权重
    'train_ratio': 0.75,                    # 训练集比例（75%）
}
```

### 关键参数说明

| 参数 | 论文建议 | 当前值 | 说明 |
|------|---------|-------|------|
| `train_ratio` | 0.7-0.8 | 0.75 | 训练集占比（论文提到70-80%）|
| `hidden_sizes` | [10, 10, 10] | [10, 10, 10] | 3层×10神经元 |
| `num_epochs` | 1500-2000 | 2000 | Phase 1训练轮数 |
| `lambda_physics` | 0.01 | 0.01 | 物理约束权重ω₁ |
| `lambda_test_physics` | 0.01 | 0.01 | 测试物理约束ω₂ |

## 🆚 与原实现对比

### 优点

1. ✅ **完全符合论文方法**
   - 每个电池单独训练
   - 不跨电池混合数据

2. ✅ **图表更准确**
   - X轴是真实循环编号
   - 曲线连续不断开
   - 易于与论文对比

3. ✅ **结果更可靠**
   - 避免不同电池间的干扰
   - 更好地反映单个电池的性能

4. ✅ **便于分析**
   - 可以看出哪个电池预测更准
   - 便于发现电池间的差异

### 缺点

1. ❌ **训练时间更长**
   - 需要训练3次（3个电池）
   - 总时间约为原来的3倍

2. ❌ **不能利用跨电池信息**
   - 每个模型只学习一个电池的模式
   - 可能泛化能力稍弱

## 🔍 关键差异总结

### 数据划分

**原实现** (`main.py`):
```
训练集 = [B05[0:60%], B06[0:60%], B07[0:60%]]  # 混合
测试集 = [B05[60%:], B06[60%:], B07[60%:]]      # 混合
↓
训练1个模型
```

**Per-Battery** (`main_per_battery.py`):
```
B05: 训练集=B05[0:75%], 测试集=B05[75%:] → 模型1
B06: 训练集=B06[0:75%], 测试集=B06[75%:] → 模型2
B07: 训练集=B07[0:75%], 测试集=B07[75%:] → 模型3
```

### 图表

**原实现**:
- X轴：Sample Index (0, 1, 2..., 120) - 混合三个电池
- 问题：曲线不连续，有断点

**Per-Battery**:
- X轴：Cycle (50, 51, 52..., 200) - 真实循环编号
- 每个电池独立子图
- 曲线连续平滑

## 📝 常见问题

### Q1: 为什么train_ratio是75%而不是60%？

**A**: 论文中提到70-80%用于训练，我们选择75%（中间值）。你可以调整为：
- 70% (更多测试数据)
- 75% (平衡)
- 80% (更多训练数据)

### Q2: 需要多长时间？

**A**:
- 单个电池：约15-20分钟（2000 epochs + 400 iterations）
- 3个电池总计：约45-60分钟
- 使用GPU会更快

### Q3: 如何只训练一个电池？

**A**: 修改`main_per_battery.py`中的`file_paths`:
```python
file_paths = [
    'data/B05_IC.csv',  # 只保留这一个
]
```

### Q4: 结果比论文差？

**A**: 可能原因：
1. IC特征提取方法不同
2. 数据预处理差异
3. 参数需要调优
4. 论文可能用了更多数据
