┌──────────────────────────────────────────────────────────────────────────────┐
│ 根本原因：验证逻辑过严                                                        │
└──────────────────────────────────────────────────────────────────────────────┘

当前代码（data_loaders/data_loader_hust.py:424-427）:
┌─────────────────────────────────────────────────────────────────────────────┐
│ # Check if cycles are exactly step_k apart for both transitions             │
│ cycle_diff_1 = self.cycle_indices[idx + self.step_k] - self.cycle_indices[idx]│
│ cycle_diff_2 = self.cycle_indices[idx + 2*self.step_k] - ...                │
│                                                                              │
│ if cycle_diff_1 == self.step_k and cycle_diff_2 == self.step_k:             │
│     valid_indices.append(idx)                                               │
│                                 ↑↑                                           │
│                         这里要求严格相等！                                    │
│                         不允许 10 != 1                                       │
└─────────────────────────────────────────────────────────────────────────────┘

问题：
  • 代码假设数据是完全连续的（相邻cycle）
  • 没有考虑稀疏采样的情况（跳跃的cycle）
  • 即使三元组等间隔（10-10-10），也会被拒绝


┌──────────────────────────────────────────────────────────────────────────────┐
│ 解决方案对比                                                                  │
└──────────────────────────────────────────────────────────────────────────────┘

方案A: 禁用三元组采样（立即可行）
──────────────────────────────────────────────────────────────────────────────
config.json: triplet_sampling.enabled = false

优点: • 立即可用，无需修改代码
     • 训练可以正常进行
缺点: • 损失二阶曲率约束
     • 预测曲线可能出现锯齿
评分: ★★★☆☆


方案B: 修改验证逻辑（推荐）
──────────────────────────────────────────────────────────────────────────────
修改后代码:
┌─────────────────────────────────────────────────────────────────────────────┐
│ # 新逻辑：允许等间隔的三元组（不限制绝对步长）                               │
│ if cycle_diff_1 > 0 and cycle_diff_1 == cycle_diff_2:                       │
│     valid_indices.append(idx)                                               │
│                                 ↑↑                                           │
│                         只要求两个间隔相等                                    │
│                         允许 [0,10,20] 因为 10==10                           │
└─────────────────────────────────────────────────────────────────────────────┘

效果对比:
  密集数据: cycles [0, 1, 2]   → cycle_diff [1, 1]   ✓ 通过
  稀疏数据: cycles [0, 10, 20] → cycle_diff [10, 10] ✓ 通过

优点: • 兼容密集和稀疏数据
     • 保留二阶曲率约束
     • 三元组物理意义不变
缺点: • 需要修改核心代码
     • 需要充分测试
评分: ★★★★★


方案C: 使用孪生采样替代（妥协）
──────────────────────────────────────────────────────────────────────────────
config.json:
  siamese_sampling.enabled = true
  triplet_sampling.enabled = false

优点: • 只需要两个样本，更灵活
     • 保留一阶平滑性约束
缺点: • 同样受稀疏采样影响（需要类似修改）
     • 损失二阶曲率约束
评分: ★★★☆☆

╔══════════════════════════════════════════════════════════════════════════════╗
║ 总结                                                                          ║
╚══════════════════════════════════════════════════════════════════════════════╝

1. 核心问题: 三元组验证要求 cycle_diff == step_k（严格相等）
             稀疏采样导致 cycle_diff >> step_k（远大于）
             → 所有三元组验证失败

2. 问题严重性: ★★★★★ (极高)
               - 训练完全无法进行（Dataset长度为0）
               - 不是性能下降，而是直接失败

3. 推荐方案: 修改验证逻辑（方案B）
             - 允许等间隔三元组（cycle_diff_1 == cycle_diff_2）
             - 兼容密集和稀疏数据
             - 保留物理约束的有效性

4. 临时方案: 禁用三元组采样（方案A）
             - 立即可用
             - 损失二阶约束，但训练可以进行
