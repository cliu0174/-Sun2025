# Exp-12 结果归档：self_trajectory 注入首次完整跑通

> 实验日期：2026-05-21
> 配置：4 模型 × 3 ratios × 3 seeds = 36 次训练
> 注入模式：self_trajectory（同电池轨迹重排）
> 注入位置：50% 生命周期
> 严重度：mild / moderate / severe
> 检测信号：6 维（input_zscore / mono_violation / rate_anomaly / drop_anomaly / trajectory_deviation / combined）

---

## 一、核心结论（TL;DR）

1. **Bug 修复奏效**：sudden_aging 的 AUC 从 ~0.5（随机）跃升到 **~0.73**，self_trajectory 注入逻辑被验证有效。

2. **trajectory_deviation 是最强信号**：跨场景平均 AUC ≈ 0.65~0.75，是当前唯一稳定有效的检测维度。

3. **`combined` 信号被噪声拖累**：对渐进场景（imbalance、resistance_rise）AUC 跌到 0.40~0.45，**低于随机水平**，原因是 `max()` 综合策略被 `input_zscore` 在正常时段的高值污染。

4. **物理约束和多尺度架构对检测能力**几乎没有贡献：4 个模型 AUC 差距 < 0.01。

5. **监督比例不重要**：ratio=1.0/0.5/0.3 的检测能力几乎一致（差距 ±0.005）。

## 五、已识别的问题

### 问题 1：`combined` 信号定义不合理 ⭐ 最重要

当前 `combined = max(归一化5信号)`，但 `input_zscore` 在正常时段就有高值（末期特征自然偏离训练均值），max() 把这些时段错误标为异常 → AUC 反向下降。

**证据**：trajectory_deviation 单列 0.65+，combined 反而 0.40。

**修复方案**（待决策）：
- 方案 A：`combined = trajectory_deviation`（最简单）
- 方案 B：`combined = 0.6 × traj + 0.4 × input_zscore`（加权）
- 方案 C：去掉 input_zscore 不参与 combined

### 问题 2：windowsize = 5 可能偏短

5 个样本算速率均值/标准差噪声大，trajectory_deviation 线性拟合对单点抖动敏感。

**建议测试**：把 window_size 从 5 增到 20，看 rate_anomaly / drop_anomaly / trajectory_deviation 是否变稳定。

### 问题 3：drop_anomaly 和 rate_anomaly 几乎没起作用

两个信号在所有场景下 AUC ≈ 0.5，未能区分异常。原因可能是：
- 5 步局部基准太短，自身就有噪声
- 模型预测本身就有平滑性，速率变化不剧烈

### 问题 4：物理约束/多尺度对检测无增益

E0 vs Eneg1，Exp09c vs A1，AUC 差距 < 0.01。说明检测能力主要来自架构本身的"对异常输入的反应"，与训练时是否加约束无关。

## 六、对论文的影响

### 6.1 可写入论文的发现

1. **"零成本异常检测"思路被验证**：在不需要额外训练、不需要真实失效电池数据的前提下，trajectory_deviation 信号能达到 AUC ≈ 0.7（突发场景）。
2. **trajectory_deviation 是核心贡献**：作为新提出的检测信号，比传统 z-score / 单调违规更有效。

### 6.2 限制条件需明示

1. 对**渐进型异常**（簇内不均衡、内阻增长）检测能力有限（AUC < 0.5 combined / 0.65 traj）。
2. 物理约束的作用主要在 SOH 预测精度，不在异常检测。
3. 检测信号需要进一步优化（combined 重新设计）。

### 6.3 如果时间允许的下一轮

1. 修复 combined 定义后重新汇总（不需要重跑训练，只需 re-aggregate）。
2. 测试 window_size = 20 vs 5 的差异。
3. 对 best 模型（Exp09c）做异常分数可视化，挑 1~2 块测试电池画时序图，直观展示 traj 信号在故障前后的跳变。
