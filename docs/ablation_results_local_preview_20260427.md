## 分析总结

### 1. Baseline 意外地强

CNN-LSTM + 软单调 + 边界约束已达到 **MAE < 0.85%、R² > 0.96**，在 HUST 77 电池跨电池测试上属于强力基线。更值得注意的是，**ratio=0.3（仅 30% 标签）时 MAE=0.799%，甚至优于 ratio=1.0 的 0.826%**——说明物理约束在低监督场景下能有效填补标签稀疏的不足，这本身就是论文的核心贡献点。

### 2. M1 注意力（E1）：效果微弱但无害

- 三个比例的改善幅度均在 ±0.5% 以内（统计噪声范围），仅 ratio=0.3 时有 3.2% 的微弱提升
- R² 在 ratio=1.0 时略有提升（0.9651 vs 0.9602），说明对全监督场景有一定帮助
- **结论**：M1 可以保留但不是核心贡献，用于论文时需谨慎表述（不宜夸大）

### 3. M2 MC Dropout（E2）：系统性退化，根本问题

- 在**所有比例**下均退化 19-26%，无一例外
- **根本原因**：当前配置 `dropout_rate=0.4` 过高，推理时保持 dropout 激活引入大量随机噪声，50 次均值无法消除系统性偏差，导致预测精度大幅下降
- 这一问题会**连带拖垮所有依赖 M2 的实验**（E5 伪标签就是典型受害者）
- **修复方向**：见下方"下一步改进方向"

### 4. M4 速率连续性（E3）：高监督有效，低监督适得其反

- ratio=1.0 和 0.5 时有稳定小幅提升（+0.5%~+0.8%），R² 也略有提高
- ratio=0.3 时退化 3.8%——**固定权重（smoothness_weight=0.05）在标签稀疏时约束过强**，速率平滑目标与预测精度目标产生冲突
- **结论**：M4 对高监督场景有效，需要自适应权重或随监督比例缩放

### 5. M5 自适应权重（E4）：仅对中间比例有效

- ratio=0.5 时效果与 M4 相近（+0.8%）
- ratio=1.0 时退化 8.6%，ratio=0.3 时退化 9.3%——**可学习权重在极端比例下过拟合或收敛不稳定**
- std 在 ratio=1.0 和 0.3 时明显低于 Baseline（0.00143 vs 0.00185），说明方差降低但均值变差，训练陷入了某种局部最优

### 6. M2+M6 伪标签（E5）：灾难性失败，根因明确

- 退化随监督比例减少而急剧恶化：ratio=1.0 时 -16%，ratio=0.5 时 -44%，ratio=0.3 时 **-59%**
- ratio=1.0 时也出现退化（-16%），说明问题不仅在伪标签本身，**M2 的基础退化是主因**
- **因果链**：M2 预测误差大 → 不确定性估计失准 → 筛选出的"高置信"伪标签质量差 → 引入错误监督信号 → 训练目标被污染 → MAE 翻倍
- **伪标签机制本身可能是合理的**，但必须先修好 M2 才能验证

## 下一步改进方向

### 优先级 P0：修复 M2 MC Dropout

**问题**：`dropout_rate=0.4` 过高。

**修复方案**：
1. 降低 dropout_rate：`0.4 → 0.1`（推荐首选）或 `0.4 → 0.2`
2. 配置文件：`configs/models/cnn_lstm_mc.json` 和 `cnn_lstm_pseudo_label.json`
3. 验证标准：E2 在 ratio=1.0 时 MAE 应接近或优于 Baseline（<0.826%）

**备选方案**（如降 dropout_rate 仍不够）：
- 训练时禁用 dropout，仅推理时开启（当前已是此逻辑，确认代码实现是否正确）
- 减少 MC 采样次数：50 → 20（加速同时降低噪声累积）

### 优先级 P1：修复后重新验证 M6 伪标签

- 前提：M2 退化问题解决后，重跑 E5
- 同时检查 `PseudoLabelManager` 的置信度阈值（当前可能过低，放进了太多低质量伪标签）
- 建议加一个 `min_confidence` 参数（如 0.95）并记录每轮实际引入的伪标签数量

### 优先级 P2：M4+M5 联合调参

- 在 M4 的基础上加入**监督比例感知的动态权重缩放**：`smoothness_weight = 0.05 × ratio`
- 这样 ratio=0.3 时权重自动降至 0.015，避免约束过强

### 优先级 P3：补跑 ratio=0.7

- 当前数据缺 ratio=0.7，论文需要 4 ratios（1.0/0.7/0.5/0.3）的完整曲线
- 建议在 P0 修复完成后、上服务器之前统一补跑

### 关于论文策略

若 M2/M6 修复后效果仍不理想，可采用以下论文写作策略：
- **核心论点**：物理约束（软单调 + 边界 + 速率连续性）在部分监督场景下已能有效稳定训练，Baseline 本身即为贡献
- **消融分析**：如实展示 M2/M6 的退化现象，并分析其原因（这本身是有价值的发现）
- **避免**：用退化模块作为最终方法的一部分声称"全面提升"
